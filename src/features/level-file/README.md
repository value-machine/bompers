# level-file

## Purpose

Level files in and out of the game: the importer that turns one HTML file with an inline `<svg data-level-format>` (or a bare `.svg` with the same root) into the engine's `LevelDefinition`, the built-in level source, the level library and the file picker. The generated public kit and the copyable AI prompt live in `level-kit` (level-gen-prompt D6). Format spec (SSOT): `documentation/game/LEVEL_FORMAT.md`; agent one-pager: `public/level-kit/v2/AUTHORING.md`.

## Decisions

- Built-in levels are real level files in `public/levels/*.html`, fetched at start (game-orchestration D4). Their drop points carry no items: crates hold the match's weapons setting, so new weapons reach them without an edit (level-direction D6). The root `data-weapons` (weapon IDs or `none`; `readWeaponsSetting` in `levelFileRoot.ts`) is the only place a level limits weapons; the kit's fire test level uses it (`torch rocket-launcher`). Both also place headbutt resets: collectible points with `data-item="dive-reset"` (start arena 3, floating garden 4; headbutt-reset D1). The importer needs nothing new for them: any `use: collectible` item ID is accepted on the role.
- Forgiving import (level-direction D3, forgiving-import): a file is rejected only when the game can't run it — no root (E1), a newer or unmigratable format (E2), no world size anywhere (E3), no spawn and no room above the terrain for one (E5), no terrain (E6). Everything else loads with a warning and a fallback (W15–W21; E4, E7, E8 retired, numbers not reused). The report alert copies its issues as plain text for the author's AI.
- A rejected import adds nothing; an accepted import with a new level id adds an entry, and one with the level id of a remembered import replaces it in place (owner, 2026-11-18, level-file-handle; was "every import is a new entry", lobby D1). Either way it becomes the lobby's level.
- Imports are remembered in this browser (`level-memory`): a saved copy everywhere, linked to the file on Chrome / Edge, re-read on window focus. A running match keeps the level it started with; a linked change shows in the lobby (owner, level direction #61, 2026-11-18).
- The built-in list is a TS manifest checked against `public/levels/` by a test, not a JSON file in that folder (lobby D6).
- The kit also ships `fire-test-level.html` (owner, fire-clusters, 2026-11-17): a level with a lot of cardboard and a torch in every drop, for testing fire by importing it in the lobby; `levelFileParser.test.ts` imports it without warnings and checks its spawns stand on the cardboard slabs.
- The kit also ships `crusher-test-level.html` (moving-parts lap B-2): a crusher with an end sound that closes fully on a wall, a squeezer that stops 20 short of a post (survivable squeeze), a spinner and a fast lift, for testing moving parts by importing it in the lobby; `levelFileParser.test.ts` (block "moving-parts test level") imports it without warnings and checks its three parts.
- `data-cell-size` is the terrain sample spacing; the shipped levels and the kit example use 4 (terrain-field D1).
- Point roles carry no behaviour in the engine yet; `data-behavior` on them is only checked (W4) (level-importer).
- `x`, `y`, `cx`, `cy` default to 0 as in SVG; sizes (`width`, `height`, `r` on terrain, `points`) are required and positive (level-importer).
- Format 2: one `terrain` role with `data-material` (behaviour) and `data-color` (looks); v1 rejected without migration and the kit moved to `/level-kit/v2/` (owner waived compatibility, material-system D1, D2, D10). Acceptance test: `services/levelFileParser.test.ts` § material system.
- An item ID on the wrong point role (catalog `use`) warns W11 and falls back like an unknown ID; the catalog `use` is the only source of role membership, and the kit preview runs the same check (import-role-warnings D1–D3).
- Moving parts (LEVEL_FORMAT § 11): `levelFileMotion.ts` reads the optional part sounds `data-move-sound` / `data-end-sound` on the group (catalog sound IDs, W4 when unknown, moving-parts B2) and each outermost `<g data-motion>` (grammar `<kind> <args> [Ns] [@phase] [pivot] [ccw]`, kind defaults so most parts need one attribute; pivot = a named bounding-box anchor, not numbers) and warns W12 (motion text) / W13 (group contents). `checkMoverSweeps` (same file) samples 48 poses per cycle and warns W14 when a part leaves bounds, overlaps static terrain, covers a spawn or outruns a player, so an agent writing blind gets alignment feedback. (moving-parts D3–D9). W13's material warning is only for a breakable material that does not burn (earth): blasts never break a part, so it acts unbreakable; a cardboard part gets no warning because it burns away (mover-materials D2, lap 2a). Whether a material burns is its fire reaction in the catalog (`reactions.fire === "burns"`, mover-materials lap 3). Since lap 4 W13 has no material warning at all: a part is made of its material like any terrain (it craters, burns and freezes), so every material is a valid choice for a part.
- Ability levels (ability-levels lap): `bobsled-run`, `piston-works`, `bonfire-bridge`, `crystal-gap` and `slush-bowl` are built-ins written by AI authors from `LEVEL_PROMPT.md`, one concept each around a set of abilities. Bobsled Run's gap is sized from a headless run: a jump with a late dive reaches about 730 units from the runway edge whatever the roll speed, so no gap can force the roll.
- Tree Grove (`public/levels/tree-grove.html`, level-objects lap 1): a built-in showing all five tree variants at several sizes on stone, earth and cardboard ground, one oak riding a sliding platform, with torch, freeze-ray and rocket crates. `levelFileParser.test.ts` (block "level objects") imports it without warnings. An object is terrain for W13 (`levelFileMotion.warnContents`).
