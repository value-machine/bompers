# combat

## Purpose

Fighting (GDD § 2 Rocket Jumping, § 3): four health chunks per player, the shared hit / damage API (front / back zones, damage from tunables), the unarmed-attack hook, the rocket launcher and the homing launcher (their crates drop in the `collectibles` feature; combat arms whoever takes one), rockets, explosions (damage to others, impulse to everyone, craters), the spawn-protection hook, and the typed sim events other systems read. Runs as sim step 3 in `match`.

Seams for later work:

- **Match rules:** set `FighterState.invulnerableUntil` (sim seconds) on respawn; replace match step 4; read `playerHit` / `playerEliminated` from `combat.events` (each consumer remembers the last `seq` it read; events live `eventRetentionSeconds`).
- **Dive** (`features/dive`): match passes its `requestDive` as `unarmedAttack`; the dive deals damage with `applyHit({ kind: "contact", source: "dive", contactPoint, direction })`; knockback is its own.
- **Hurt reaction:** an explosion calls the player feature's `reactToHit` with the impulse it gave each other player; the victim rolls as hard as the blast pushed it (a close, strong blast sends it flying, with one low hop on a hard landing since roll-spin-bounce, 2026-11-18; the edge of the range only shoves; player `roll.ts`). The shooter is only pushed, never rolled, so rocket jumps stay in control (dive-headbutt D10).
- **Sound:** event `type` → SFX (`rocketFired`, `explosion`, `playerHit`, `playerEliminated`, `pickupCollected`); `terrainDestroyed.soundId` / `effectId` come from the catalog material.
- **Effects:** explosion, impact pop and debris live in the `effects` feature (reads `combat.events`). The rocket tube is drawn by the player renderer, as part of the blob's silhouette.
- **More items:** a new id in `WeaponItemId` (`src/shared/types/weaponItems.types.ts`) and `src/shared/config/weaponItems.ts`, its `MODE_OF` row in `weapons.ts` (and a `KIND_OF` row if it fires rockets) and a tunables section; if it flies differently, a new `RocketKind`; a held weapon that is not a rocket is a `spray` weapon behind the `sprayAttack` hook (the torch, fire-spread b1).
- **Terrain gone:** `reportTerrainDestroyed(combat, { cleared, at, timeSeconds, soundId? })` (in `explosions.ts`) turns any `ClearedCells` into `terrainDestroyed` events (one per material + colour, with the catalog effect / sound; `soundId` replaces the material's sound when what destroyed it has its own, `"none"` silences it); blasts use it, and match uses it for fire burn-outs, once per debris spot of a batch with only the first one sounding, as fire's `burn-out`. Its crate drops in `collectibles` (combat D2: pickups moved there); the catalog item makes it a weapon a level's `data-weapons` can name.
- **Spray weapons (ice-element D4):** the torch and the freeze ray are both held spray weapons; their ray fan is the shared `src/shared/utils/rayFan.ts` (`castRayFan` from the helmet point, `pushAlongAim`), called by the fire and ice features. The `sprayAttack` hook gets the held weapon's `itemId`, and the start cue is the `sprayStarted` event with that id (was `torchStarted`). A new spray weapon is an id in `SprayWeaponItemId`, a row in `SPRAY_TUNABLES` and in `SPRAY_BEAM` (`weapons.ts`: its ray fan and element) and a branch where match fills the hook.
- **Beam clash (owner, beam-clash D1, the "Steam wall"):** two held beams whose elements react end each other where they meet, and nothing of either gets past (no fire, no chill, no push). The rule is the shared `src/shared/utils/beamClash.ts` (`resolveBeamClashes`): both beams reach out from their helmet at the same pace and end at the same distance; a beam that would get there later ends on the other's side, which keeps its length; terrain between them counts. `stepAttacks` works it out for all sprayers before any of them sprays, so the order of the players does not matter, hands each `sprayAttack` call its `reach` (the hook must not act past it) and keeps this step's clashes in `CombatState.beamClashes`. Which elements react is the pair table in `beamClash.ts` (D2): fire × ice is the only row, and beams of the same element pass through each other. A new reacting pair is a row there; a new beam is a `SPRAY_BEAM` row. The combat overlay draws the steam at each clash (`drawClashSteam`, from the sim time alone), and sound reads the count for `steam-hiss`. `combat.beamClash.thickness` (4 units) is how close beams must come to touch. Moving parts count as terrain for the clash: the rule casts against the arena's `terrainBodies`, so a beam behind a part does not reach the meeting (mover-materials lap 1). Since mover-materials lap 3 a beam's element is an `ElementId` (`fire`, `cold`) and which pairs react is the shared element pair table (`src/shared/utils/elementPairs.ts`; fire × cold `cancel`), which the clash rule reads; a clash's `reaction` is that table's word, and steam is how a cancel between beams looks.
- **Tuning:** every number (also the crate drop schedule, `combat.drops`, read by `collectibles`) is in the `combat` section of `src/shared/config/gameTunables.ts`.

## Decisions

- Combat state is a `GameState.combat` slice keyed by player id; `PlayerState` only carries motion (combat D1).
- The fire cooldown only holds a weapon's own next shot: once the last rocket has left, an unarmed press goes to the `unarmedAttack` hook at once (dash-feel lap; it was dropped for up to 0.7 s).
- Events carry a monotonic `seq` and are pruned by age, so several sim steps per frame never hide one (combat D3).
- Elimination flags the fighter; match step 4 does the respawn (combat D4).
- Launcher: 6 rockets, no time limit, dropped when empty or on elimination (combat D5).
- Drops: first after 3 s, then every 7 s while fewer than 2 lie in the arena, round-robin over drop points — the sim has no randomness source (combat D6). The crates themselves live in `collectibles` since the pickups-to-collectibles lap (D1 there).
- Each weapon names the crater shape its blast cuts (`craterShape`, `src/shared/types/craterShape.types.ts` + its distance rule in `src/shared/utils/craterShape.ts`); rocket and homing are `"round"`. A new shape is a new union member plus its rule (terrain-field D5, owner blast-power D17).
- One blast power per explosion (0–100, each weapon's `power`; rocket and homing 50) sets everything in straight lines: reach `reachPerPower · P`, centre push `pushPerPower · P` falling off to `minFalloff`, crater reach `craterPerPower · P` ÷ the material's toughness (`combat.blast`; blast-power D1, D3, D10). Power 50 reproduces the pre-power blast (push 1080, reach 64, crater 34). Distance is measured to the nearest point of the body box (combat D8). Replaces combat D7 (separate push / crater radii).
- The blast hands each pushed player one `{ direction, impulse }` through `reactToHit`; the roll strength lives in the reaction, so the shared-roll lap replaced the tumble threshold without touching blast code (blast-power D12, shared-roll D7).
- Knockback and impulses still apply during spawn protection; only damage is blocked.
- Every shot has recoil (`combat.rocket.recoil`, applied by `fireRocket` through `kickShooter` in `rockets.ts`, kept apart from the rocket's touch / bounds logic): an instant velocity change opposite the aim, on the ground and in the air, so firing is also movement (down-shots hop or slow a fall, level shots push back, mostly felt in the air). An upward kick leaves the ground. It stacks with a rocket jump's blast, so match's `outOfBoundsMargin` counts it in the fastest launch (jumps-and-recoil D2). The blast impulse was scaled down with gravity (D1 in the player README) while `tumble.minImpulse` stayed, so only close blasts (within about a quarter of the radius) tumble victims (jumps-and-recoil D3).
- Every attack deals damage through `applyHit`; how much is the `combat.hitDamage` table by hit kind (`contact`, `blast`, `burn`) and zone (`front`, `back`), never per-attack code. Defaults: contact 1 / 2, blast 1 / 1 (combat D10, owner scope change), burn 1 / 1 per tick (a burning blob, source `fire`; two ticks per burn, fire-burn D5, D10).
- A crouching victim (`PlayerState.crouching`) takes `floor(damage × combat.crouchDamageScale)` (0.5): halved, rounded down, so a 1-chunk hit deals 0 and still lands (owner feedback round 2 § 2.4; crouch D1, D2). A `burn` hit is not halved: ducking doesn't stop fire (fire-burn D5); crouching instead skips a burn's second tick, decided in the fire feature (D10). One step in `applyHit` via `crouchDamage`; knockback and the tumble reaction are unchanged. Rockets, blasts and beams hit the player's `hurtBox`, which is lower while crouching, and player's `hurtCenter` and combat's `helmetPoint` sink with it, so a crouched blob is aimed at and fires from where it is drawn (owner, crouch-sink D4). The api exports `helmetPoint` for features that aim from a blob; they aim at one with player's `hurtCenter`.
- Homing launcher (owner request 2026-11-16, "homing but dodgeable"): a second weapon whose missiles are rockets of kind `homing` in the same list and flight path (homing-missiles D1). Dodge rule (D2, numbers in `combat.homing`): target locked at launch = the nearest live opponent within 70° of the aim (none → straight); 0.2 s straight before steering; 480 u/s (1.4 × run speed) with at most 2.6 rad/s of turn, a turn radius of ≈ 185 units, so a late jump or sidestep makes it overshoot; steering fuel 1.6 s, then straight; air-burst at 3 s; same blast as a rocket. 3 missiles per crate, 0.7 s cooldown, recoil 120 (D3). `rocketFired` carries `kind`.
- Beam clash (owner, beam-clash D1, 2026-11-18, options page https://claude.ai/artifact/Gudavw2magY98kCggPsTen): "Steam wall", over a wall pushed by walking in, the fresher beam cutting through, and a steam burst that shoves both blobs back. It lives in combat because combat already knows who sprays what each step, so the fire and ice features still do not import each other; the match only passes `reach` on. Whole beams end at the meeting distance (not ray by ray), so a wide flame does not lick around a narrow ray.
- Combat has no unarmed attack of its own: the dive lap provides it, plugged in through the `unarmedAttack` hook (combat D11, owner scope change).
- Moving parts (moving-parts lap B-2): `eliminateFighter` takes cause `crush` with a `CrushSqueeze` (normal out of the part toward the victim, and which part); the event carries it to the knockout layer. The credit is the same as for a fall (last hitter within `killCreditSeconds`, owner D13). Cause `self` (never-stuck lap): the player held the respawn button; same credit as a fall. `reportPartSound` logs a `partSound` event for a moving part's author-declared sound, so the sound layer plays it like a terrain sound.
- `reportTerrainDestroyed` needs only the removed looks (`byLook`), so a fire batch merged over several bodies (the ground and moving parts, mover-materials-l2) reports through it without a sample box, which belongs to one grid. Blasts cut every body they reach through the arena's `clearCraterOnBodies` (mover-materials lap 4: blasts break moving parts like terrain).
- Spray recoil (owner, spray-recoil, 2026-11-23: "push the player slightly off the ground, not close to a rocket jump"): one mechanism for every spray weapon, `sprayRecoil` in `attacks.ts`, run from `spray` after the `sprayAttack` hook. **D1** a continuous thrust opposite `weaponAim` while fire is held: the spray weapon's own `recoil` (units / s², the held counterpart of a rocket's per-shot kick in units / s; torch and freeze ray 3200 ≈ 2.3 × gravity). **D2** lift cap: the thrust may add at most `combat.sprayRecoil.airBudget` (500 u/s) between two touches of the ground (`FighterState.sprayRecoilLeft`, refilled every grounded step, sprayed or not). Straight down from standing: 0.16 s of thrust, apex ≈ 50 units (a fifth of a jump, ~1/8 of a rocket jump's 417), then it lands and hops again; holding all 3 s of fuel climbs no higher, so it never hovers. In the air it slows a fall by up to 500 u/s. **D3** sideways cap: it pushes along the push only while slower than `combat.sprayRecoil.maxSideSpeed` (240 u/s, under run speed 340), so it never outruns walking; on the ground the thrust is just above ground decel (3000), so a level spray slides the blob back slowly (≈ 100 units in 1 s), walking forward overcomes it, and in the air it pushes harder (air decel 700). **D4** interactions: a seated kart driver and a diving blob are steady (match passes `steadyShooter`: the kart and the dive own that motion); a frozen blob cannot fire, so none; crouching does not block it (on the keyboard, down is both crouch and aim down, and blocking it would kill the lift; crouch's own braking soaks most of a sideways push); a roll keeps it, along the swept aim (spin-fire D1); burning changes nothing. The kill-zone margin is unchanged: 500 u/s is below one rocket's blast plus recoil (1280), and a blob holds one weapon. **D5** no extra juice: the spray's own sound and visual already mark the moment, and the hop lands with the blob's existing landing squash and sound, so no new sound, shake or flash (the recoil is feel, not a new moment in `GAME_JUICE.md`).
- Weapons fire along the player's `weaponAim` (owner, spin-fire D1, v0.45.0): rockets, the homing lock cone, recoil and the beam clash, swept round while rolling. `helmetPoint` turns round the body centre with `rollAngle`, as the helmet is drawn (spin-fire D3).
- Bonus damage (freeze-ray buff B, 2026-11-20): `CombatState.bonusDamage` holds extra chunks the next direct hit on a slot takes this step; `applyHit` adds it (not to fire: it melts, it does not break), uses it up and flags the `playerHit` event `bonus`. The match fills it each step from frozen blobs (`ice.blob.shatterDamage`), so every direct-hit path (dive, headbutt, rockets, blasts) shatters a block the same way, without combat knowing about ice.
- Getting hurt (owner, hurt-feedback D1, 2026-11-20): the over-head health bar pops to 2× and settles back over `feel.hurt.barPopSeconds` whenever health drops; at `feel.hurt.lowHealth.chunks` or fewer the blob's outline pulses in its colour and sweat flicks off (`lowHealth` layer, placed under the players by the match).
- Health hearts and healing (owner, health-pickups D2, D3, D6): the over-head health chunks are hearts (shared `drawInkHeart`) in the player colour, lost ones in `healthLost`, outlined with the zoom-clamped prop width; the row is enlarged so a heart is never under 9 px on screen. `healFighter` gives a hurt player chunks back, never above `combat.maxHealth`, and counts it in `healCounts` (the pickup sound). The bar pops on a heal as on a loss, but not on the refill of a respawn.
- A knocked-out blob leaves the players in play; its over-head bar hides from the knockout until the respawn (`hideBarsOutOfPlay`) instead of staying frozen where it was hit (owner, death-health-bar).
- **Kart hits (kart lap K7):** `HitSource` has `kart`: the match turns a kart running into a blob faster than `karts.hitSpeed` into `applyHit` (kind `contact`, credited to the driver), so the hurt feedback (sound floor, pose, chunk pops) is the same as any contact hit. Rockets also explode on a kart's chassis (`roundBodies`).
- **Rockets explode on physics objects (physics-objects lap):** `stepCombat` takes optional `roundBodies` (circles); a rocket touching one explodes like on a player. The blast itself is unchanged; the physics-objects feature reads this step's `explosion` events and pushes balls by `blastHitPushAt` ÷ weight.
